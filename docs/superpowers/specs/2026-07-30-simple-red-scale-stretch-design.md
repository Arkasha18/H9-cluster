# Simple Red: растянутая шкала

## Задача

Шкалы Simple Red — окружности. Требуется сделать их «не совсем окружностью»:
левая половина спидометра остаётся на месте, правая оттягивается вправо на
настраиваемое число пикселей. Тахометр растягивается зеркально, влево, чтобы
пара приборов осталась симметричной.

## Форма

Окружность разрезается сверху и раздвигается: контур идёт **дуга →
горизонтальная вставка → дуга**.

```
дуга 1:   θ от 20° до 90°,   смещения нет
вставка:  θ стоит на 90°,    смещение идёт от 0 до X
дуга 2:   θ от 90° до 200°,  смещение равно X
```

Решения, стоящие за формой:

- **Рез ровно в вершине окружности.** Это единственное место, где
  касательная уже горизонтальна, а значит единственное, где горизонтальная
  вставка стыкуется с обеими дугами без угла. При наклоне шкалы в 20°
  вершина приходится на 78 км/ч.
- **Вставка одинаковой длины на всех радиусах.** Дуга, риски, подписи,
  лента прогресса и подложка раздвигаются на одну и ту же величину,
  поэтому толщина кольца сохраняется, а «на X пикселей» значит ровно X
  пикселей на любом слое.
- **Отсчёт по длине контура, а не по углу.** Иначе между риской до
  вставки и риской после неё образуется дыра в X пикселей там, где
  остальные идут через ~20, и на плоском участке не окажется ни одной
  риски. По длине они распределяются ровно.

### Зеркальность

Формы приборов — зеркальные отражения относительно вертикали. Тахометр
проходит ту же вставку со сдвигом: приходит к нулевому смещению, а не
уходит от него, поэтому раздвигается его ближняя к центру экрана половина.
Раскладка при этом не переворачивается — 0 остаётся слева.

## Касательная

`scaleTangentX`/`scaleTangentY` не декоративны: `drawScaleText` строит по ним
нормаль и утапливает подписи на `MAIN_SCALE_LABEL_OFFSET` внутрь. Без учёта
вставки подписи вокруг неё уедут не туда.

Обход по длине делает касательную единичной везде:

```
(dx, dy) = (sin θ, −cos θ) · L
```

На вставке θ стоит на 90°, где синус равен единице, а косинус нулю, —
то есть ровно горизонтальный шаг. Одна и та же формула работает на дугах и
на вставке, а значит касательная непрерывна в обоих стыках, и ни один из
них не читается как угол. Параметр `rightGauge` касательной не нужен:
смещение на дугах постоянно, а на вставке даёт единичный наклон.

## Дуги → Path

`Canvas.drawArc` рисует только овалы, поэтому на семплированный `Path`
переходят:

| место | стоимость |
|---|---|
| `SimpleRedBackground.drawFullArc` — шкала, красная зона, свечение | фон рисуется один раз офскрин |
| `SimpleRedBackground.drawTachBackdrop` — кольцевой сектор | там же |
| `SimpleRedClusterView.drawProgressBand` — 7 проходов | каждый кадр |

Лента строится в переиспользуемый `Path` через `rewind()`: аллокаций в кадре
не добавляется, как и в остальном коде этого слоя.

Семплирование задаётся **по длине контура**, а не по доле шкалы, потому что
сектор подложки выходит за её пределы на `TACH_BACKDROP_PADDING_DEGREES`.
96 сегментов на весь контур дают погрешность ~0.04 px при R=260.

## API

В `SimpleRedLayout` добавляются примитивы по длине контура, через которые
выражается всё остальное:

```java
static float SCALE_STRETCH_X
static float SCALE_TOTAL_LENGTH
static float angleAtLength(float lengthAlong)
static float stretchOffsetAtLength(float lengthAlong, boolean rightGauge)
static float pointXAt(float lengthAlong, float radius, boolean rightGauge)
static float pointYAt(float lengthAlong, float radius)
static float scaleLength(float fraction)
```

`radialX`/`radialY` становятся обёртками над ними через `scaleLength(fraction)`,
поэтому риски, подписи и блум на конце ленты следуют за формой без правок.

## Осознанные компромиссы

`SweepGradient` ленты остаётся угловым относительно центра прибора, а вставка
чуть меняет полярный угол точек — передний край градиента разойдётся с концом
ленты на пару градусов. Блум позиционируется через `radialX`/`radialY`, то есть
точно. Альтернатива — `LinearGradient` вдоль пути — того не стоит.

Отсчёт по длине сдвигает подписи: доля 0.5 приходится уже за вставкой, а не на
середину развёртки. Это неизбежная плата за ровный шаг рисок.

## Проверка

`SimpleRedLayout` не зависит от Android, тесты идут на JVM:

- до реза контур совпадает с прежней окружностью с точностью до 0.001 px;
- вставка строго горизонтальна и раздвигает шкалу ровно на `SCALE_STRETCH_X`;
- оба её конца лежат в вершине окружности;
- касательная постоянна по модулю и совпадает с центральной разностью в
  обоих стыках — то есть углов нет;
- шаг между соседними рисками одинаков по всей шкале, включая вставку;
- зеркальный инвариант приборов;
- вычитание смещения возвращает чистую окружность — форма выключается одним
  числом;
- приборы не пересекаются при разумных `X`.

`SimpleRedBackground` и `SimpleRedClusterView` — Android-классы, форма
проверяется глазами через `PreviewActivity` со скриншотом на эмуляторе.

## Настройка

`SCALE_STRETCH_X` — константа в `SimpleRedLayout`, рядом с `GAUGE_RADIUS` и
`SCALE_START_DEGREES`. Текущее значение 54.0f.

В проекте есть неиспользуемый фреймворк `SkinSettingsProvider` с редактором в
общем экране настроек. Выводить туда одно число не стоит: `SimpleRedLayout`
целиком статический, и живая настройка потребовала бы снять со `static` всю
геометрию. Когда значение устаканится, разумно вывести его в настройки вместе
с другими параметрами скина отдельной задачей.
