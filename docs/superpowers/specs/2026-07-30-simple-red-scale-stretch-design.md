# Simple Red: растянутая шкала

## Задача

Шкалы Simple Red — окружности. Требуется сделать их «не совсем окружностью»:
левая половина спидометра остаётся на месте, правая оттягивается вправо на
настраиваемое число пикселей. Тахометр растягивается зеркально, влево, чтобы
пара приборов осталась симметричной.

## Форма

Накладка зависит только от угла и не зависит от радиуса:

```
левая шкала:  x = cx − R·cos θ + X · max(0, −cos θ)²
правая шкала: x = cx − R·cos θ − X · max(0, +cos θ)²
y = cy − R·sin θ                     (без изменений)
```

`X` — `SCALE_STRETCH_X`, максимальное отклонение. Достигается при θ=180°;
на конце шкалы (θ=200°) выходит 0.88·X.

Решения, стоящие за формулой:

- **Накладка не зависит от радиуса.** Все слои прибора — дуга, риски,
  подписи, лента прогресса, подложка — смещаются на одну и ту же величину,
  поэтому толщина кольца сохраняется, а «на X пикселей» значит ровно X
  пикселей на любом слое.
- **Квадрат, а не `max(0, −cos θ)`.** Линейная накладка даёт скачок
  производной на вертикали: касательная поворачивается разом на `atan(X/R)`
  ≈ 5° при X=24, и на обводке в 3 px это читается как излом. У квадрата
  производная в вертикали равна нулю с обеих сторон, стык незаметен.
- **Ноль левее вертикали.** `max(0, ·)` обнуляет накладку на всей левой
  половине спидометра, так что она остаётся точно такой, как сейчас.

Экранная вертикаль (θ=90°) при наклоне шкалы в 20° приходится на долю
**0.389**, а не 0.5.

### Зеркальность

Формы приборов — точные зеркальные отражения относительно вертикали:

```
d_right(180° − θ) = −d_left(θ),   где d = x − центр прибора
```

Раскладка тахометра при этом не переворачивается: 0 остаётся слева,
растягивается его внутренняя половина, к центру экрана. Зеркалится только
накладка, не базовая окружность.

## Касательная

`scaleTangentX`/`scaleTangentY` не декоративны: `drawScaleText` строит по ним
нормаль и утапливает подписи на `MAIN_SCALE_LABEL_OFFSET` внутрь. Без учёта
растяжки подписи на растянутом конце уедут не туда.

Производная берётся аналитически:

```
dx/dθ = sin θ · (R + 2X·|cos θ|)   в растянутой зоне
dx/dθ = sin θ · R                   вне её
dy/dθ = −R · cos θ                  (без изменений)
```

Обе ветви совпадают в вертикали. `scaleTangentX` получает параметр
`rightGauge` — накладка теперь разная у приборов.

## Дуги → Path

`Canvas.drawArc` рисует только овалы, поэтому на семплированный `Path`
переходят:

| место | стоимость |
|---|---|
| `SimpleRedBackground.drawFullArc` — шкала, красная зона, свечение | фон рисуется один раз офскрин |
| `SimpleRedBackground.drawTachBackdrop` — кольцевой сектор | там же |
| `SimpleRedClusterView.drawProgressBand` — 7 проходов | каждый кадр |

Лента строится в переиспользуемый `Path` через `rewind()`: аллокаций в кадре
не добавляется, как и в остальном коде этого слоя.

Семплирование задаётся **по углу**, а не по доле шкалы, потому что сектор
подложки выходит за пределы шкалы на `TACH_BACKDROP_PADDING_DEGREES`.
96 сегментов на 180° дают погрешность ~0.04 px при R=260.

## API

В `SimpleRedLayout` добавляются угловые примитивы, через которые выражается
всё остальное:

```java
static float SCALE_STRETCH_X
static float stretchOffsetAt(float angleRadians, boolean rightGauge)
static float pointXAt(float angleRadians, float radius, boolean rightGauge)
static float pointYAt(float angleRadians, float radius)
```

`radialX`/`radialY` становятся обёртками над ними через `scaleAngle(fraction)`,
поэтому риски, подписи и блум на конце ленты следуют за формой без правок.

## Осознанные компромиссы

`SweepGradient` ленты остаётся угловым относительно центра прибора, а
растяжка чуть меняет полярный угол точек — передний край градиента разойдётся
с концом ленты на пару градусов. Блум позиционируется через `radialX`/`radialY`,
то есть точно. Альтернатива — `LinearGradient` вдоль пути — того не стоит.

## Проверка

`SimpleRedLayout` не зависит от Android, тесты идут на JVM:

- накладка ровно нулевая на левой половине спидометра;
- максимум равен `SCALE_STRETCH_X` и достигается при θ=180°;
- производная непрерывна в вертикали;
- зеркальный инвариант `d_right(180°−θ) = −d_left(θ)`;
- приборы не пересекаются при разумных `X`;
- при `SCALE_STRETCH_X = 0` геометрия совпадает с окружностью — то есть
  растяжка выключается одним числом.

`SimpleRedBackground` и `SimpleRedClusterView` — Android-классы, форма
проверяется глазами через `PreviewActivity` со скриншотом на эмуляторе.

## Настройка

`SCALE_STRETCH_X` — константа в `SimpleRedLayout`, рядом с `GAUGE_RADIUS` и
`SCALE_START_DEGREES`. Стартовое значение 24.0f, около 9% радиуса.

В проекте есть неиспользуемый фреймворк `SkinSettingsProvider` с редактором в
общем экране настроек. Выводить туда одно число не стоит: `SimpleRedLayout`
целиком статический, и живая настройка потребовала бы снять со `static` всю
геометрию. Когда значение устаканится, разумно вывести его в настройки вместе
с другими параметрами скина отдельной задачей.
