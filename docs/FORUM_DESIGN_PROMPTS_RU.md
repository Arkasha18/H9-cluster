# Создание нового скина H9 Cluster в Codex

Инструкция предназначена для локального Codex, который видит рабочую папку,
может изменять реальные файлы и запускать сборку. Перед началом выполните
`CODEX_LOCAL_SETUP_RU.md` и распакуйте используемые ZIP-архивы.

## Единственные обязательные ограничения дизайна

Источник истины — каталог
`H9_Cluster_Neutral_Design_Template_1920x720`.

### 1. Окно Яндекс карты

Карта выводится штатной системой под приложением. Итоговый скин обязан быть
полностью прозрачным во всей белой области файла
`02_yandex_map_transparency_mask.png`.

Координаты подтверждённого окна на холсте 1920×720:

- `(745, 105)` — верхняя левая точка;
- `(1173, 105)` — верхняя правая точка;
- `(1287, 719)` — нижняя правая точка;
- `(632, 719)` — нижняя левая точка.

На границе окна должен сохраняться чёрный градиент. Готовый технический слой
находится в `04_yandex_map_black_gradient_rgba.png`. Его можно использовать
непосредственно либо точно воспроизвести его альфа-переход.

### 2. Зоны системных значков

`03_system_icons_forbidden_mask.png` получен из красной разметки владельца
автомобиля. Исходный шаблон 1280×480 перенесён в рабочие 1920×720 точным
масштабом ×1,5. Маску нельзя расширять, уменьшать или заменять приблизительными
прямоугольниками.

- Белый: не размещать графику скина, текст, шкалы, цифры, рамки, свечение или
  динамические показания.
- Чёрный: эта маска ограничений не задаёт.

Это collision-маска, а не прозрачное окно. Она нужна для проектирования и
проверки, а не для вырезания частей уже готового изображения.

### Всё остальное свободно

Форма и положение приборов, набор и расположение датчиков, цвета, шрифты,
размеры, композиция, слои и способ отрисовки определяются автором скина.
Нейтральный шаблон не требует копировать Classic и не задаёт мест для
спидометра, тахометра, карточек, топлива, температуры, одометра или шин.

Техническое требование приложения не является ограничением дизайна:
изменяющиеся значения и указатели должны оставаться динамическими и получать
данные из источника, а не быть запечены в статический фон.

## Этап 1 — визуальный макет

Результат этапа: один утверждённый PNG 1920×720. Android-проект и APK на этом
этапе не создаются.

```text
Ты работаешь локально через Codex.

Найди каталог `H9_Cluster_Neutral_Design_Template_1920x720`, полностью прочитай
`README_RU.txt` и открой `01_technical_guide.png`.

Создай один визуальный концепт нового скина приборной панели H9 Cluster в PNG
1920×720. Не копируй оформление Classic, если я прямо не прошу об этом.

У дизайна только два обязательных ограничения:

1. Белая область `02_yandex_map_transparency_mask.png` предназначена для
   штатной Яндекс карты и должна оставаться свободной. На её границе сохрани
   чёрный переход из `04_yandex_map_black_gradient_rgba.png`.
2. Не размещай никакую графику и информацию в белых областях
   `03_system_icons_forbidden_mask.png`. Используй точную маску без расширения
   и сокращения. Это collision-маска, не вырезай ею уже нарисованные элементы.

За пределами этих двух зон компоновка полностью свободна. Самостоятельно
предложи форму приборов, набор и расположение показаний, стиль, цвета и
типографику с учётом моих визуальных референсов.

Покажи только фронтальное изображение экрана без салона, руля, перспективы и
физической рамки дисплея. Примерные значения допустимы только для демонстрации
композиции.

Сохрани результат в `02_mockup/approved_mockup.png`, покажи его и остановись.
Не создавай Android-проект, отдельные слои или APK до моего утверждения.
```

Для точечной корректировки утверждаемого макета:

```text
Сохрани остальную композицию без изменений. Исправь только:

1. [ТОЧНАЯ ПРАВКА].
2. [ТОЧНАЯ ПРАВКА].

Повторно проверь обе технические маски и покажи обновлённый PNG 1920×720.
```

## Этап 2 — автономный Demo-проект

Результат этапа: отдельный Android Demo-проект с динамическими тестовыми
данными, предпросмотрами и debug APK. Он не подключается к автомобилю.

В рабочей папке должны находиться:

- утверждённый макет;
- распакованный `H9_Cluster_Dashboard_Demo_Base_Source_v3.zip`;
- распакованный нейтральный шаблон.

```text
Ты работаешь локально через Codex внутри выбранной рабочей папки.

На основе утверждённого PNG реализуй автономный Android Demo-проект. Исходный
Demo используй только как техническую основу для Canvas, состояния и
генератора тестовых значений. Его оформление не является визуальным образцом.

ЛОКАЛЬНЫЕ ПУТИ

- утверждённый макет: [ПУТЬ];
- корень Demo-проекта: [ПУТЬ];
- нейтральный шаблон: [ПУТЬ];
- дополнительные ассеты и шрифты: [ПУТИ ИЛИ НЕТ].

Сначала:

1. найди все входные файлы;
2. прочитай README, Gradle-файлы, Manifest и исходники Demo;
3. проверь `git status`/`git diff`, если это Git-репозиторий;
4. проверь JDK, Android SDK, Gradle Wrapper, Pillow и NumPy;
5. собери неизменённый baseline debug APK;
6. сообщи фактические результаты и найденные пути.

После baseline реализуй утверждённый дизайн на Canvas 1920×720:

- отдели статические RGBA-слои от динамических значений;
- не запекай в фон изменяющиеся цифры, указатели или индикаторы;
- сохрани разделение `DashboardView`, `DashboardState`,
  `DashboardDataSource` и `DemoDashboardDataSource`;
- тестовый источник должен проходить минимумы, максимумы и промежуточные
  значения всех реализованных показаний;
- движения стрелок и маркеров должны соответствовать геометрии нового дизайна.

У дизайна только две обязательные проверки:

1. Итоговый alpha равен 0 во всей белой области
   `02_yandex_map_transparency_mask.png`, а граница карты использует чёрный
   переход из `04_yandex_map_black_gradient_rgba.png` либо точную реализацию.
2. Ни один статический или динамический элемент не пересекает белую область
   `03_system_icons_forbidden_mask.png`. Не изменяй размеры этой маски и не
   применяй её как clipPath к уже готовому дизайну.

Все другие решения по расположению и виду элементов бери только из
утверждённого макета. Никаких дополнительных ограничений Classic нет.

До сборки изменённого APK создай и покажи:

- полный кадр 1920×720 с тестовыми значениями;
- кадр поверх тестовой карты;
- контрольный кадр с наложенной системной collision-маской;
- отчёт автоматической проверки двух масок.

После моего подтверждения собери debug APK, проверь его содержимое и укажи
абсолютный путь, размер и SHA-256. Не добавляй APK в Git.
```

## Этап 3 — отдельный скин в основном приложении

На этом этапе утверждённая отрисовка переносится в H9 Cluster, а тестовые данные
заменяются реальным общим источником. Дизайн нового скина должен оставаться
изолированным от других скинов.

```text
Ты работаешь локально через Codex.

Перенеси утверждённый Demo-дизайн в основной H9 Cluster как отдельный скин.
Существующие скины визуально не меняй.

ЛОКАЛЬНЫЕ ПУТИ

- окончательный Demo-проект: [ПУТЬ];
- основной H9 Cluster: [ПУТЬ];
- нейтральный шаблон: [ПУТЬ];
- скриншоты проверки в автомобиле: [ПУТИ ИЛИ НЕТ];
- имя нового скина: [ИМЯ].

Сначала изучи оба проекта, сохрани пользовательские изменения, собери baseline
основного приложения и подготовь таблицу:

элемент скина → поле Demo → поле общего ClusterState → реальный data ID →
формат → диапазон → поведение при отсутствии данных.

Архитектура:

- сбор реальных данных, `ClusterState` и `GwmClusterDataSource` остаются общими;
- новый скин получает собственный каталог ассетов и собственный рендерер;
- вся геометрия, координаты, цвета, шрифты и отрисовка нового скина находятся
  внутри его модуля/папки;
- подключение скина к общему приложению ограничивается минимальной регистрацией
  в фабрике/реестре и пунктом выбора темы;
- удаление каталога скина и его регистрации не должно менять другие скины.

Не переносить из Demo тестовый источник, тестовый цикл, package name или
тестовые значения. Не менять реальные Binder/data ID без доказанной
необходимости.

После переноса повторно проверь только два ограничения дизайна:

1. прозрачное окно Яндекс карты и чёрный градиент его границы;
2. отсутствие любых элементов скина в точной системной collision-маске.

Также проверь компиляцию, выбор нового скина, реальные форматы данных и
отсутствие визуальных изменений существующих тем.

Сначала покажи полный контрольный кадр и список изменений. APK, установка,
commit, push и PR выполняются только после моего отдельного подтверждения.
```

## Публикация и безопасность

- Не публикуйте production-ключи и пароли.
- APK и каталоги `build` не включаются в Git.
- Слова «собрано», «установлено» и «проверено» допустимы только после
  фактической команды и проверки результата.
- Финальная проверка выполняется на автомобиле с видимыми системными значками
  и работающей картой.
