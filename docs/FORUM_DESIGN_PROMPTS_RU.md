# Создание нового скина H9 Cluster

Правила сверены с `main` версии 9.7.0 и проверкой Sculpted Titanium на автомобиле
28 октября 2026 года. Начинайте с текущей `main`: старый автономный Demo v8 не
содержит всех возможностей приложения. Окружение описано в
[CODEX_LOCAL_SETUP_RU.md](CODEX_LOCAL_SETUP_RU.md), действующие скины — в
[галерее](SKINS_RU.md) и
[контракте рендереров](../app/src/main/java/net/adminrunet/h9cluster/skins/README.md).

В Forum Kit эти же инструкции доступны отдельно, а шаблон — и отдельными
файлами, и вложенным ZIP. Ссылки на `app/`, `tools/` и остальные документы
относятся к актуальному репозиторию; для работы с кодом загрузите `main`.

## 1. Сначала состав и компоновка, затем оформление

У нового скина должны быть собственные формы приборов, материалы, свет и
типографика. Замена цвета существующего ION AURORA или набор цифр в одинаковых
прямоугольниках не решают задачу нового дизайна. Изучите существующие темы,
чтобы сохранить функциональность, затем сформулируйте отличия нового стиля.

Работайте в координатах **1920×720**, фронтально, без салона, руля и перспективы.
Сначала распределите все показания из таблицы ниже и оставьте широкую область
карты. Скорость и тахометр по возможности сдвигайте к внешним краям вместе с
их корпусами; точное положение зависит от выбранной композиции.

Сохраните паспорт компоновки: для каждого показания — поле данных, единицы,
формат, прямоугольник, опорная точка, центр и baseline текста, размер шрифта,
допустимая длина и состояние «нет данных». Отдельно задайте траектории шкал и
свободную область карты. Таблица или JSON должны лежать рядом с исходниками.
Это координаты конкретного дизайна, а не обязательная сетка всех будущих скинов.

После согласования расположения **зафиксируйте опорные точки**. Оформляйте
корпуса, фаски, стекло, контуры и свет вокруг них; затем точно подгоните рисунок
под цифры. Если нужно перенести показание, явно обновите паспорт и покажите
изменение. Не перестраивайте всю композицию при каждой правке оформления.

### Обязательные показания

Все перечисленные показания должны присутствовать одновременно. Не заменяйте
их придуманными датчиками; температуры шин в `ClusterState` нет.

| Показание | Источник / правило |
| --- | --- |
| Скорость, км/ч | `speedKph` через общий `SpeedDisplayMode`; одно значение для цифр и шкалы |
| Обороты, об/мин | `rpm`; плавная шкала и отдельно стабилизированные цифры |
| Номер передачи | `currentGear`: только 1…8 при `gearSelector == D`, в штатной зоне сверху |
| Общий пробег ODO, км | `odometerKm` |
| Пробеги Day и Trip, км | `dayKm`, `tripKm` — два отдельных значения |
| Топливо, л; запас хода, км | `fuelLiters`, `rangeKm` |
| Охлаждающая жидкость, °C | `coolantC` |
| Масло АКПП / ATF, °C | `transmissionTemperatureC` с проверкой свежести |
| Наружная температура, °C | `outsideTemperatureC`, включая отрицательные значения |
| Угол руля, ° | `steeringAngleDeg`, знак и понятное направление поворота |
| Давление четырёх шин, bar | `tyreFrontLeftBar`, `tyreFrontRightBar`, `tyreRearLeftBar`, `tyreRearRightBar` |
| Скорость четырёх колёс, км/ч | `wheelFrontLeftKph`, `wheelFrontRightKph`, `wheelRearLeftKph`, `wheelRearRightKph` |
| Крутящий момент, Н·м | `engineFlywheelTorque` |
| Мгновенный расход | `instantFuelConsumption`: л/ч при измеренной скорости 0–1 км/ч, иначе л/100 км |
| Средний расход, л/100 км | `consumptionLitersPer100Km`; не `journeyAverageFuelConsumption` из журнала поездки |
| Напряжение, В | `voltage` |
| Текущее время и дата | системные часы, общий `DashboardClock`; не статическая подпись |
| Wi-Fi | общий `WifiIndicator`, реальное состояние соединения |

Для колёс однозначно обозначьте FL/FR/RL/RR или их русские эквиваленты.
Отсутствующее/некорректное значение показывайте прочерком согласно контракту
поля. Устаревший ATF (15 секунд) также становится недоступным. Не подменяйте
отсутствие данных нулём, демонстрационным числом или новым источником скорости.
Часы и Wi-Fi не являются датчиками автомобиля, но входят в обязательный макет.

## 2. Технические поля: где фон допустим, а где запрещён

Исходные файлы находятся в
[нейтральном шаблоне](H9_Cluster_Neutral_Design_Template_1920x720).
`03_system_icons_forbidden_mask.png` — точная RGBA-геометрия v2.4. Учитывайте
**все пиксели с alpha > 0**, включая полупрозрачную кромку. Имя `forbidden`
историческое: не все поля требуют отверстия в декоративном фоне.

| Поле | Допустимое оформление | Кто рисует показания |
| --- | --- | --- |
| Штатные значки по краям | Декор может проходить под ними; важные цифры, подписи и указатели разместите вне поля | Штатная система поверх приложения |
| Верхняя центральная зона коробки | Корпус/фон допустим под штатной зоной | Буквы P/R/N/D и ручной M с номером рисует система; скин добавляет только автоматический номер 1…8 |
| Режим движения справа внизу | Декор допустим; отдельную карточку с NORMAL/ECO и т. п. не добавлять | Штатная система |
| Два внутренних поля слева внизу | Никакой добавленной графики, текста, рамок, свечения или динамики; запас не менее 1 px | Сохранить исходную подложку и видимость штатного слоя |

Точные нижние левые поля получаются пересечением alpha слоя 03 с областями
`[387,373,498,442)` и `[230,494,548,642)`; здесь правая и нижняя границы
исключены. Это **выбор частей исходной маски**, а не замена фигур прямоугольниками.
В них 40 651 пиксель с ненулевой alpha. Готовая маска этих полей — файл 06,
остальные системные поля — файл 07; цветное наложение обеих групп — файл 05.
Геометрия и правила также записаны в `system_fields.json`.

Автоматический номер передачи имеет исключение: узкая область
`[982,28,1018,66)`, центр X=1000, baseline Y=63, Rajdhani 44. Букву D рядом
не дублируйте. При P/R/N/M, неизвестном селекторе или номере вне 1…8 скин
ничего не добавляет. Фиксированную штатную зону нельзя переносить вслед за
дизайном приборов.

Слой 03 и производные 05–07 нужны для **проектирования и проверки**. Они не
входят в APK как оформление, не запекаются в фон и не применяются как clipPath
или ластик к готовой картинке. Сначала разместите элементы правильно, затем
проверьте пересечения. Нельзя исправлять ошибку вырезанием букв и шкал по маске.

Это правила нового дизайна по согласованной композиции Titanium. Существующие
скины могут иметь более строгий договор: например, у ION AURORA весь foreground
свободен от 03, кроме номера передачи, а отдельный космический фон согласован
под штатным слоем. Не ослабляйте его тесты ради нового скина.

## 3. Карта и плавные края

Штатная карта находится **под** приложением и видна через alpha готового
Canvas. `04_yandex_map_black_gradient_rgba.png` — откалиброванный чёрный RGBA
исходник. Сохраните его байты, размер и положение; не рисуйте похожую подложку
заново. `02_yandex_map_transparency_mask.png` устарела: не используйте её как
границу карты, маску прозрачности или проверку. Видимая карта не ограничена
одним условным прямоугольником.

Допустима отдельная, воспроизводимая обработка **рабочей копии** слоя 04 при
подгонке перехода, если паспорт описывает её и тесты подтверждают результат.
В Titanium верхняя полоса плавно ослабляется на Y=40…79, а исходный PNG остаётся
неизменным. Это пример, не обязательный эффект для каждого скина.

- Сохраните полную прозрачность центрального ядра калибровки:
  X=672…1095, Y=80…719. Более широкую область без добавленного декора задайте
  в паспорте конкретного скина; у Titanium это X=560…1359, Y≥80.
- В нижних левых защищённых полях сохраняется **alpha исходной подложки**.
  Проверка «alpha=0» относится к добавленному foreground, а не ко всей композиции.
- Растушуйте собственные внутренние края оформления. Не допускайте резкой
  прямоугольной границы с картой, одиночных пикселей, ореолов, растянутой верхней
  строки и шва вокруг площадки передачи. Проверяйте масштаб 100% и увеличенные
  фрагменты, а не только уменьшенный красивый эскиз.
- Проверьте RGBA на чёрном, шахматном, светлом и тёмном фоне карты. Чёрный фон
  рекламного скриншота — отдельная подложка предпросмотра; его нельзя запекать
  в прозрачное окно production-скина.

Растровые слои экспортируются строго в 1920×720 без изменения пропорций.
При переходе SVG → PNG → Android проверьте alpha и premultiplication.
Никакая проверочная карта или шахматка не должна попасть в рабочий APK.

## 4. Читаемые цифры и движение приборов

Центрируйте цифры и подписи относительно **внутренней поверхности своего
прибора**, а не края PNG. Используйте измерение текста и метрики шрифта;
сохраните baseline и визуальный центр при смене разрядности. Единицы измерения
и подписи имеют собственные фиксированные опорные точки. Свет и рёбра корпуса
не должны пересекать читаемую область.

Динамические цифры, время, значки состояния и подвижные указатели не запекаются
в фон. При извлечении оформления из эскиза удалите образцы чисел, букв и
системных значков. Перерисуйте повреждённые участки корпуса, не растягивайте
случайную строку пикселей поверх старой надписи.

Каждая шкала калибруется по окончательной геометрии отдельно: таблица
`значение → X → Y` для нуля, максимума и подписанных делений, движение между
ними по траектории, одинаковый отступ и правильное направление указателя.
Не зеркальте шкалу тахометра со спидометра без проверки геометрии. После
изменения формы повторите проверку контрольных и промежуточных значений.

Для тахометра разделите плавность движения и читаемость цифр. Используйте
общий `RpmReadoutStabilizer`: минимум 160 мс между обновлениями, округление до
10 об/мин и гистерезис 8 об/мин. Все повторные цифровые показания одного RPM
получают одно стабилизированное значение; шкала продолжает двигаться плавно.
Стабилизатор находится в слое отображения: не фильтруйте им исходный
`ClusterState`, события двигателя или журнал поездки. Проверьте запуск,
остановку и быстрый набор/сброс оборотов, а не только один статический кадр.

Скорость проходит через общий `SpeedDisplayMode`: реальная, +4,5% либо +5 км/ч
с существующим плавным вводом поправки на малой скорости. Цифры и шкала
совпадают, на стоянке остаётся ноль. Не добавляйте вторую поправку внутри скина.
Переключение единиц расхода зависит от **измеренной**, а не поправленной скорости.

## 5. Три этапа и готовые задания

Этапы разделяют результаты работы, а не требуют повторного разрешения на
каждую команду. Если пользователь уже поручил дизайн, реализацию и сборку,
продолжайте в этом объёме. Запрашивайте только недостающее решение; согласованные
координаты и разрешения сохраняются. Если поручен лишь эскиз, закончите эскизом.

### Этап 1 — компоновка, дизайн, подгонка

```text
Изучи актуальную main H9 Cluster, docs/FORUM_DESIGN_PROMPTS_RU.md,
контракт рендереров и нейтральный шаблон. Сначала проверь git status:
не затирай текущую работу. Загружай upstream main, не подменяй её старым Demo.

Создай новый самостоятельный стиль приборки 1920×720. Составь полный паспорт
показаний из обязательной таблицы, размести скорость и тахометр ближе к
внешним краям и сохрани широкую карту. На первом проходе реши компоновку.
На втором оформи корпуса, материалы, свет и типографику вокруг закреплённых
координат; затем подгони оформление, не смещая согласованные показания.

Системные поля по краям, сверху и справа внизу допускают декоративный фон
под штатным слоем. Нижние левые поля 06 остаются свободными от добавленной
графики с запасом 1 px. Рисуй только номер автоматической передачи в её
штатном месте, без букв селектора, driveMode и копий штатных ламп.

Сохрани редактируемый исходник, паспорт и четыре фронтальных изображения:
на чёрном фоне; на тёмной карте; на светлой карте; с цветным наложением
реальных технических полей 05. Добавь легенду к наложению, не подменяй поля
набором нарисованных значков. Подпиши демонстрационные значения как макет.
Проверь полный состав показаний, поля, центровку и края при масштабе 100%.
Покажи результат и продолжи только ту реализацию, которая уже поручена.
```

При точечной правке сохраняйте паспорт и остальные координаты; после правки
повторно выдайте чистый вид и тот же вид с техническими полями.

Проверяйте читаемость мелких подписей и интервалы между названием, числом и
единицами при масштабе 100%. Для Day/Trip проверяйте также длинные значения:
число не должно касаться подписи соседней строки. Если пользователь поручил
разнести этот блок, обновите его координаты и интервалы в паспорте явно.

Прозрачность проверяйте и на контрастном нижнем слое с текстом. Ослабление
подложки может открыть штатные часы сверху и штатный пробег под Day/Trip снизу.
Эти фрагменты не видны на чёрном фоне и не обнаруживаются проверкой пересечения
с масками. Сохраняйте калиброванную подложку 04 целиком, если её изменение не
проверено на автомобиле. Для APEX SPORT используется исходная 04 без изменения
пикселей. Исправляйте подложку, не добавляйте вырезание по техническим
маскам или прямоугольники поверх штатных предупреждений. После восстановления
исходной alpha отдельно покажите верхнюю и нижнюю границы на тёмной и светлой
картах; проверьте длинный штатный пробег в нижнем слое и foreground отдельно.

### Этап 2 — рендерер и Demo текущего приложения

Предпочтителен build type `demo` **этого же репозитория**. Так проверяются тот
же `ClusterState`, настройки, сглаживание и двухэкранная модель. Автономный
`H9_Cluster_Dashboard_Demo_Base_Source_v3.zip` оставлен как учебный Canvas-пример
v8.0.7; его `DashboardState` и старый отчёт сборки не подтверждают полноту и
работоспособность нового скина.

```text
Реализуй согласованный дизайн отдельным скином в актуальном H9 Cluster.
Сохрани независимые renderer/assets и подключи его через SkinRegistry.
Используй общий ClusterState, SpeedDisplayMode, RpmReadoutStabilizer,
DashboardClock и WifiIndicator. Доступ к автомобильным сервисам не добавляй
в рендерер. Исходники других скинов не заменяй.

Отдели статическое оформление от всех изменяемых показаний. Проверь нативный
Canvas-рендер в Robolectric: ноль, движение, максимум, длинные пробеги,
отрицательная температура, разные единицы расхода, нет/устарели данные,
все состояния селектора и несколько кадров изменения RPM. Добавь тесты
геометрии шкал и alpha по паспорту, включая foreground отдельно от подложки.
Технические маски используй только для проверки, не как вырезание оформления.

Сначала получи PNG из реального View без эмулятора. Сравни его с макетом,
проверь чёрный фон, две карты и наложение полей. Собери assembleDemo,
проверь отсутствие автомобильных .so и секретов в Demo APK. Штатные лампы,
буквы селектора и driveMode разрешены только в демонстрационном верхнем слое.

Если запуск эмулятора поручен, следуй двухэкранной проверке из инструкции
окружения. Не включай overlay_display_devices: это создаёт наложения и
зеркалирование. При тормозах или рекурсивных экранах останови тестовый
экземпляр, не запускай новые экземпляры и не меняй AVD вслепую.
Отчитайся отдельно о сборке, нативных рендерах и фактически проведённом запуске.
```

### Этап 3 — реальные данные и выпуск

```text
Подготовь production-вариант с реальными показаниями. Убедись, что DEMO_MODE
выключен, данные поступают из общего автомобильного источника, а тестовые
числа, карта, лампы, буквы селектора и driveMode не нарисованы скином.
Автоматический номер передачи должен остаться в штатной верхней зоне.

Выполни проверки CI для затронутого кода и нативный тест production-alpha.
Укажи фактические variant, applicationId, versionName/versionCode и сертификат
APK. Тестовую подпись используй только в согласованном тестовом варианте;
она не превращает Demo в сборку с реальными данными. Не удаляй установленное
приложение ради обхода несовпадения подписи и не теряй его настройки.

Если установка на автомобиль уже поручена, установи согласованный APK на
указанное устройство и проверь результат на стоящем автомобиле. Если доступ
не предоставлен, передай APK и точный список непроверенных условий. Проверяй
скорость, RPM, передачу, карту и настоящие штатные предупреждения совместно.
Не скрывай окно предупреждений большим чёрным прямоугольником: его

Публикацию выполняй только если она поручена: обнови версию, описание релиза

подписанный production APK штатным release pipeline репозитория. Для форума
```

## 6. Критерии готовности

| Проверка | Что должно быть подтверждено |
| --- | --- |
| Комплектность | Все строки таблицы, дата/время/Wi-Fi; только номер D, без дублей штатных показателей |
| Дизайн | Самостоятельный стиль, оформленные приборы, сохранённые опорные точки, свободная карта |
| Типографика | 0 / 8 / 88 / 188, 800 / 1500 / 8000 RPM, длинные ODO/Day/Trip, минус и прочерки помещаются без скачков центра |
| Технические поля | Цветной overlay точной геометрии; добавленный слой пуст в 06 и на 1 px вокруг; декор разрешён в 07 |
| Alpha | Исходник 04 неизменен; центральное ядро прозрачно; нижняя левая подложка сохранена; нет швов на двух картах |
| Динамика | Калибровка обеих шкал, плавное движение RPM и спокойные цифры, общая настройка скорости |
| Production | Реальный источник, без Demo-наложений; обработка настоящих системных уведомлений сохранена |
| Доказательства | Исходники, паспорт, нативные рендеры, результаты проверок и точная идентификация APK |

Нативный рендер подтверждает геометрию, но не поведение композитора автомобиля.
Успешная сборка не подтверждает запуск, а Demo не подтверждает реальные данные.
Если в машине скорость застыла на нуле или осталось штатное окно, сравните
состояние источника с работой штатного приложения и временем событий. В нашей
проверке такой эпизод исчез вместе с восстановлением штатного состояния
двигателя; это не доказывает неисправность скина. Не исправляйте его выдуманными
показаниями и не объявляйте причину установленной без соответствующих данных.
