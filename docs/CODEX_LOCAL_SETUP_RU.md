# Подготовка локального компьютера для разработки дизайна H9 Cluster в Codex

Требования к разработке скинов сверены с `main` v9.7.0, 28 октября 2026 года.

Эта инструкция предназначена для трёхэтапного процесса:

1. компоновка показаний, оформление и подгонка дизайна к закреплённым координатам;
2. реализация отдельного скина и проверка Demo текущего приложения;
3. проверка production-варианта с реальными данными и, если поручено, выпуск.

Обычный веб-чат для второго и третьего этапов не подходит: агент должен иметь
доступ к локальной папке, изменять файлы, запускать Python, Gradle и Android SDK.

## 1. Установите Codex

### Рекомендуемый вариант для macOS и Windows

Установите новое настольное приложение ChatGPT, в которое входит режим Codex:

https://chatgpt.com/download/

После установки:

1. войдите в свой аккаунт ChatGPT;
2. в левом верхнем меню выберите `Codex`;
3. нажмите добавление проекта;
4. выберите подготовленную локальную рабочую папку;
5. запускайте каждый этап в отдельном потоке Codex, но в той же рабочей папке.

Не запускайте эти промпты в обычном ChatGPT в браузере или на телефоне: там
режим Codex с прямым доступом к локальной папке не выбирается. Если на
компьютере установлено приложение `ChatGPT Classic`, скачайте новое приложение
по ссылке выше.

Codex следует давать доступ только к рабочей копии проекта. Не выбирайте
домашнюю папку целиком, корень диска или каталог со всеми личными документами.

### Codex CLI для macOS и Linux

Официальный установщик:

```sh
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

После установки:

```sh
codex
```

Выберите `Sign in with ChatGPT`.

### Codex CLI для Windows

Запустите PowerShell:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"
```

После установки:

```powershell
codex
```

Альтернативный способ для компьютера, где уже установлен Node.js:

```sh
npm install -g @openai/codex
```

Официальный исходный код и актуальные способы установки:

https://github.com/openai/codex

## 2. Установите Android Studio

Скачайте актуальную стабильную версию:

https://developer.android.com/studio

При первом запуске завершите Setup Wizard. Затем откройте:

`Tools → SDK Manager`

Во вкладке `SDK Platforms` установите:

- `Android 15 / API 35` — необходим для `compileSdk = 35`;
- `Android 11 / API 30` и совместимый system image — для двухэкранного Demo
  на эмуляторе. Нужны API ≥29 и `activities_on_secondary_displays`.
  Целевой автомобиль остаётся Android 9 / API 28; более новый эмулятор
  проверяет компоновку, но не заменяет проверку на машине.

Во вкладке `SDK Tools` установите:

- Android SDK Build-Tools 35.x;
- Android SDK Platform-Tools;
- Android SDK Command-line Tools (latest);
- Android Emulator — если планируется эмулятор.

NDK и CMake этому Java-проекту не требуются.

Не прописывайте путь Android SDK в общий архив проекта. Локальный путь при
необходимости хранится в `local.properties`, который не публикуется.

## 3. Проверьте JDK 17

Android Gradle Plugin 8.x требует JDK 17. Android Studio поставляется с
JetBrains Runtime, но Codex запускает Gradle из терминала, поэтому отдельно
проверьте:

```sh
java -version
```

В выводе должна быть версия 17. Если подходящего JDK нет, установите Eclipse
Temurin 17:

https://adoptium.net/temurin/releases/?version=17

После установки настройте `JAVA_HOME` на JDK 17 или дайте Codex найти JDK 17,
поставляемый вместе с Android Studio. Не фиксируйте абсолютный путь к JDK в
публикуемых исходниках.

## 4. Установите Python

Скриптам подготовки и проверки изображений нужны Python, Pillow и NumPy.

Скачать Python:

https://www.python.org/downloads/

Рекомендуется создать виртуальное окружение внутри рабочей папки.

macOS/Linux:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements-tools.txt
```

Windows PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements-tools.txt
```

Команды выполняются из корня актуального репозитория. Папку `.venv` нельзя
включать в итоговый ZIP. Генератор шаблона использует встроенный Noto Sans, чтобы
кириллица и размеры подписей совпадали на Windows, macOS и Linux CI.

## 5. Установите Git

Git не является частью Android-приложения, но нужен для безопасного просмотра
изменений и возврата к исходному состоянию:

https://git-scm.com/downloads

Работайте с копией проекта. Перед каждым этапом сохраните исходный ZIP отдельно
и проверьте текущее состояние файлов.

## 6. Подготовьте рабочую папку

Основной рабочий вариант — одна актуальная копия репозитория. В ней Demo и
production используют один рендерер; второй Android-проект создавать не нужно.
Для новой копии можно загрузить только `main`:

```bash
git clone --single-branch --branch main https://github.com/Arkasha18/H9-cluster.git
```

В существующей копии сначала проверьте `git status`; сохраните незавершённую
работу и осознанно обновите рабочую ветку из `origin/main`. Не используйте
`reset --hard` ради обновления. Пример структуры:

```text
H9-cluster/
├── docs/H9_Cluster_Neutral_Design_Template_1920x720/
├── app/src/main/java/net/adminrunet/h9cluster/skins/
├── app/src/main/assets/dashboard/skins/
├── tools/assets/
└── artifacts/skin-review/
    ├── layout.json
    ├── preview-black.png
    ├── preview-map-dark.png
    ├── preview-map-light.png
    └── preview-technical-fields.png
```

Рабочие изображения и фотографии в `artifacts/` не публикуются автоматически.
Паспорт и исходники готового скина перенесите в его каталог `tools/assets/`.

В актуальном нейтральном шаблоне находятся:

- `02_yandex_map_transparency_mask.png` — устаревшая справочная маска,
  сохранённая только ради совместимости с опубликованными ссылками; она не
  задаёт фактические границы карты и не используется при создании или
  проверке скина;
- `03_system_icons_forbidden_mask.png` — точная геометрия полей v2.4,
  включая полупрозрачные края;
- `04_yandex_map_black_gradient_rgba.png` — готовая чёрная подложка,
  откалиброванная на реальном автомобиле;
- `05_system_fields_overlay.png` — цветное наложение полных технических полей;
- `06_lower_left_reserved_mask.png` — нижние левые поля, свободные от
  добавленной графики с запасом 1 px;
- `07_factory_overlay_fields_mask.png` — остальные поля: декор допустим
  под штатными значками, селектором и режимом движения;
- `system_fields.json` — точные координаты, правила и хеши исходников.

Исходник 04 сохраняется неизменным. Обработка его рабочей копии для плавного
края допускается с описанием и alpha-тестами; в нижних левых полях сохраняется
alpha исходной подложки. Проверочные маски нельзя запекать в фон или применять
для вырезания готового дизайна. Скин добавляет только номер 1…8 при D в верхней
штатной зоне, а буквы селектора и `driveMode` рисует система. Полный состав
показаний и процесс описаны в [FORUM_DESIGN_PROMPTS_RU.md](FORUM_DESIGN_PROMPTS_RU.md).

`H9_Cluster_Dashboard_Demo_Base_Source_v3.zip` содержит учебный однодисплейный
пример v8.0.7. Он сохранён для прежних ссылок, но не является актуальным
контрактом данных или двухэкранной демонстрацией. Для нового скина используйте
`assembleDemo` текущего репозитория. Production-ключ для этого не нужен.


## 8. Проверка без рекурсивных экранов

Сначала используйте нативные рендеры Robolectric и alpha-тесты. Эмулятор
запускайте только если такая проверка нужна и входит в поручение. Одного
launcher-окна недостаточно: приложению нужны два независимых экрана.

- Основной логический display 0 — настройки. Его разрешение задаётся AVD;
  запишите фактическое значение, не приписывайте ему размер приборки.
- Приборка — логический display 2, **1920×720, 240 dpi**, `OWN_CONTENT_ONLY`.
- Используйте штатный `emu multidisplay`, проверяя итог через `dumpsys display`.
  Индекс дисплея в консоли эмулятора может отличаться от Android display ID.
- Не включайте `overlay_display_devices` в настройках разработчика: окно
  поверх основного экрана может зеркалировать его и создавать рекурсию.

Для Windows есть [tools/start_titanium_demo.ps1](../tools/start_titanium_demo.ps1):
он проверяет API и display ID, убирает старый developer overlay, создаёт
отдельный экран и устанавливает Demo. Существующие посторонние дисплеи он
не перенастраивает. Выберите реально установленный AVD; имя по умолчанию
не означает, что такой образ присутствует на вашем компьютере.

Новый тестовый экземпляр запускается только с `-StartEmulator`: 2 ядра,
2048 МБ RAM, без загрузки и сохранения snapshot. Перед запуском проверьте
доступные ресурсы. При тормозах или вложенных копиях экрана прекратите тест
и закройте именно этот экземпляр. Не повторяйте запуск вслепую. Если проверка
была кратковременной, завершите её закрытием тестового эмулятора.

## 9. Разрешения и объём работы

Codex может запросить разрешение:

- читать и изменять выбранную рабочую папку;
- запускать Python, Gradle и Android SDK;
- скачать зависимости Gradle при первой сборке;
- использовать эмулятор или подключённое ADB-устройство.

Проверяйте точную команду и путь перед подтверждением. Работа над новым скином
в основной копии разрешена уже на этапе Demo; секретный ключ для неё не нужен.
Согласованное поручение сохраняется между этапами: не запрашивайте повторное
разрешение на уже порученные сборку, commit, push или установку. Если установка
или публикация ещё не поручены, подготовьте проверяемый результат и уточните
только этот следующий шаг.

## 10. Варианты APK и подпись

- Demo APK собирается только с debug-подписью.
- `demo`: `net.adminrunet.h9cluster.demo`, `DEMO_MODE=true`, тестовые данные,
  без автомобильных ARM64 `.so` и TBOX-секретов.
- `debug`: `net.adminrunet.h9cluster.fdbusprobe`, `DEMO_MODE=false`,
  диагностический вариант; это не обычный Demo.
- `release`: `net.adminrunet.h9cluster`, `DEMO_MODE=false`, реальные данные.
  Публичный релиз подписывается production-ключом штатным release pipeline;
  локальный APK с тестовой подписью нельзя выдавать за такой релиз.
- Не помещайте `.p12`, `.jks`, пароль, `key.properties` или команды с паролем
  в форум, Git, промпт либо итоговый ZIP.
- Установка на автомобиль выполняется, когда пользователь её поручил, на
  стоящей машине. Проверяйте сертификат: не удаляйте приложение и настройки
  ради обхода конфликта подписи.
