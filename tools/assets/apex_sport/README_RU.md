# APEX SPORT — дизайн приборной панели

Самостоятельный спортивный макет 1920×720: два круглых прибора в тёмных металлических корпусах, белые шкалы, красные указатели, отдельные дуговые указатели топлива и температуры двигателя. Круги Ø320 расположены по краям; между боковыми блоками оставлен коридор карты шириной 800 px.

Основа — загруженная из GitHub `origin/main`, коммит `242a66b0b51a7cac7e54a4d528f899a154238f76`. Рабочая ветка — `arkadiy/apex-sport-design`. Компоновка согласована пользователем и реализована отдельным `ApexSportClusterView`, ID `apexsport`. Результаты проверки реализации описаны в `IMPLEMENTATION_RU.md`; этот документ описывает редактируемый дизайн и его экспорт.

## Файлы

- `design.svg` — редактируемые формы и текст со встроенными шрифтами, рабочая копия калиброванной подложки и отдельные группы оформления, шкал и демонстрационных значений.
- `design-outlined.svg` — переносимая версия с текстом в векторных контурах; выглядит одинаково без установки шрифтов.
- `generate.mjs` — воспроизводимый исходник компоновки, оформления, экспорта и проверок. Числовые опорные точки заданы в первом проходе; второй проход строит оформление вокруг них. Отдельно отмечена запрошенная после проверки в машине перестановка Day/Trip в две горизонтальные строки.
- `layout.json` — паспорт всех 27 показаний: поля, единицы, форматы, прямоугольники, опорные точки, центры, baseline, шрифты, допустимая длина, крайние образцы и отсутствие данных. Здесь же шкалы, их калибровочные точки, правила системных полей и преобразование рабочей подложки.
- `layout-wireframe.svg` — компоновка с прямоугольниками показаний и baseline.
- `chrome.svg` — отдельное оформление без чисел, надписей, шкал и стрелок.
- `readouts.svg` — шкалы, подписи, цифры и состояние макета; демонстрационные значения нельзя использовать как фон production.
- `map-dark.svg`, `map-light.svg`, `preview_maps.py` — вымышленные карты для проверки прозрачности, не навигационные данные и не ресурсы приложения.
- `renders/01-black.png`, `02-map-dark.png`, `03-map-light.png`, `04-technical-fields.png` — четыре фронтальных изображения в исходных 1920×720.
- `validation.json` — результат пиксельной проверки и хеши.

## Компоновка и правила

Скорость: центр корпуса `(228,330)`, цифровое значение `(228,349 baseline)`. Тахометр: корпус `(1692,330)`, значение `(1692,346 baseline)`. Внешний радиус корпуса 160 px; читаемые риски заканчиваются на r122 с учётом толщины. Декоративный обод проходит под частью штатной внешней дуги, как разрешено текущим контрактом. Числа, подписи и указатели остаются вне неё.

Топливо и ОЖ: центры `(466,238)` и `(1454,238)`, дуговые шкалы E–F и C–H, собственные подвижные указатели и числовые значения. Топливо откалибровано на 0…80 л согласно текущему источнику приложения; ОЖ — 40…130 °C согласно текущим Classic/Sport. Красные участки — графическое обозначение краёв шкалы, не новая логика автомобильных предупреждений.

Коридор `[560,80,1360,720)` свободен от добавленного оформления. Полностью прозрачное ядро `[672,80,1096,720)` сохранено. Для двух нижних левых полей сохранена исходная alpha подложки 04; все пиксели маски 06 и их однопиксельная окрестность свободны от нового foreground.

Номер автоматической передачи стоит строго в `[982,28,1018,66)`: Rajdhani 44, центр X=1000, baseline=63. Показывается только 1…8 при D; буквы селектора, driveMode и штатные лампы не добавлены. На проверочном изображении наложен исходный `05_system_fields_overlay.png` в масштабе 1:1 и дана легенда. Поля не заменены значками; 03/05/06/07 не используются для вырезания графики.

Паспорт сохраняет обязательные правила будущей реализации: общий SpeedDisplayMode; плавная шкала RPM и общий стабилизатор цифр; расход по измеренной скорости; отдельные Day/Trip; свежесть ATF не более 15 секунд; отсутствие данных как прочерк, пустой невалидный номер передачи; реальные часы/дата и общий WifiIndicator. Направление руля в образце обозначено знаком и векторной стрелкой; соглашение о знаке исходного сигнала нужно подтвердить при реализации.

Все значения, время, Wi-Fi, стрелки и карты являются демонстрационными. В каждом кадре есть надпись «МАКЕТ • ВСЕ ЗНАЧЕНИЯ ДЕМОНСТРАЦИОННЫЕ».

## Подгонка и подложка

Перед первым согласованием при визуальной проверке размер скорости уменьшен со 100 до 92 px с сохранением `(228,349)`, подписи запаса хода и ATF опущены с baseline309 на 316, подпись руля поставлена рядом с неизменным значением.

После проверки на стоящем автомобиле 28 октября 2026 пользователь попросил увеличить часы и мелкие надписи и разделить подписи Day/Trip с числами. В новой редакции все размеры текста увеличены ровно на **1 px в логической сетке 1920×720**: часы 34→35, дата 24→25, основные подписи 13→14, единицы 15→16, `bar` и `км/ч` в таблице 14→15, `КОЛЕСО` 12→13. Числовые показания, подписи шкал и оформление также получили +1 px. Размер номера автоматической передачи остаётся 44 px по контракту; общий `WifiIndicator` не меняется.

Day и Trip теперь имеют две горизонтальные строки: подпись по X=416, число по X=490, отдельное `км` по X=548. Baseline чисел остаются 675 и 707, размер чисел — 26 px, ширина — 88 px; подписи и единицы — 12 px на baseline 674 и 706. Единицы здесь белые, чтобы не теряться у края подложки на светлой карте. Между контурами подписи и числа требуется не менее 8 px, между числом и единицей — не менее 4 px, в том числе для `9999.9`. ODO остаётся в `(321,694)`, размер 28 px, ширина 153 px. Остальные числовые координаты сохраняются. Этот запрос пользователя — явное исключение из первоначального закрепления X для Day/Trip; он отражён в паспорте.

Вероятная причина артефакта слева от часов — добавленное в первой редакции ослабление верхней подложки: переход Y40…79 уменьшал её непрозрачность и позволял просвечивать нижнему слою. Сам renderer не рисовал штрихи в этой области; каким именно штатным текстом они были, по фотографии подтвердить нельзя. В ревизии 9.7.1 верхняя подложка восстановлена из калиброванной 04 без изменения alpha; дополнительный верхний переход удалён. Исправление не рисует новый прямоугольник поверх штатных предупреждений и не использует технические маски для вырезания оформления. В области часов Y0…78 непрозрачны, Y79 сохраняет исходный сглаженный край alpha128, с Y80 начинается карта. На светлой карте верхняя граница заметнее прежнего плавного перехода.

После следующей фотографии с просвечивающими цифрами под Day/Trip в ревизии **9.7.2** удалён и оставшийся нижний переход Y647+. Он ослаблял исходную непрозрачную нижнюю полосу 04 и позволял видеть показания нижнего штатного слоя. Теперь **вся подложка 04 используется побайтно без изменения alpha или RGB**, включая исходную нижнюю полосу. Типографика 9.7.1, координаты показаний и белые единицы `км` у Day/Trip сохранены.

Резкая нижняя граница — часть исходной калибровки 04. Она не сглаживается новым полупрозрачным слоем, не строится по маске и не заменяется закрывающей заплатой. Исходные поля 06, их запас 1 px и прозрачное ядро сохраняются. Светлые просветы, видимые на светлой карте внутри 06, относятся к неизменной исходной калибровке. Паспорт описывает отсутствие любых преобразований подложки; генератор проверяет побайтное совпадение PNG и всех декодированных RGBA-пикселей.

## Воспроизведение

Нужны Node.js с `sharp` и `@napi-rs/canvas`. При использовании встроенного runtime Codex путь к пакетам передаётся через `NODE_PATH`; абсолютные пути компьютера не зашиты в исходники. Для повторного создания карт достаточно Python 3 без сторонних пакетов.

Из корня репозитория:

```bash
python tools/assets/apex_sport/preview_maps.py
node tools/assets/apex_sport/generate.mjs
node tools/assets/apex_sport/export.mjs
python -m unittest discover -s tools/tests -p test_skin_design_template.py
```

Генератор перезаписывает только файлы этого дизайна и вспомогательные проверки в `artifacts/skin-review/apex-sport/`. Отдельный `export.mjs` обновляет только `app/src/main/assets/dashboard/skins/apexsport/`: корпуса без текста, неизменную 04 и NotoSans. Для изменения показаний или оформления редактируйте `generate.mjs`; JSON — полный экспортируемый паспорт. Отдельные SVG можно редактировать в векторном редакторе, однако повторная генерация заменит их.

Проверяются все ненулевые alpha маски, запас 1 px, отсутствие важных показаний в 03 за исключением передачи, прозрачность ядра, свободный коридор, сохранение alpha под 06, полная идентичность подложки 04, размеры и вмещение крайних строк, промежутки Day/Trip. После изменения необходимо повторить нативный экспорт и визуальный просмотр кадров и фрагментов при 100%; фактические результаты сборки и проверок записываются отдельно в `IMPLEMENTATION_RU.md`. Эти проверки подтверждают статический дизайн; новую редакцию отдельно проверяют на реальном дисплее автомобиля.
